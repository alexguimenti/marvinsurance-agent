The Copilot's graph

How backend/agent/copilot/graph.py runs a turn: five nodes, two decisions, and a pause for the handler to confirm a payout.

How a turn runs

1. Plain

recall → model → tools → model → … → save → END. The model ↔ tools loop repeats until the model answers without asking for a tool.

2. With a sign-off

When a tool sets state.sign_off, the graph goes to confirm. The turn is waiting until the handler presses a button.

3. Resuming

The app sends Command(resume="sign_off" | "cancel"). Only sign_off pays; the outcome goes back to the model as a confirmation message.

Every tool goes through carded: it records a step in the app before the tool runs and closes it as done, refused or failed. Each step is a card in the sidebar. There are 18 tools of its own (reads, actions and waiting) plus the context layer's tools over MCP, and the model may call only one at a time.

confirm does nothing before interrupt(): LangGraph runs the whole node again when it resumes, so anything before it would happen twice.

State and context

CopilotState (saved in each checkpoint)

messages, model_calls (reset each turn), cost_usd, notes, sign_off.

Asker (context_schema)

The handler's sign-in, who they are, and turn_id. It comes in the graph's context, never the state or the config, so it is never saved in a checkpoint.

Limit

A 26th model call in one turn raises TooManyModelCalls.
